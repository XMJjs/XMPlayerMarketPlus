# XMPlayerMarketPlus 模拟玩家逻辑验证报告

> 目的：以真实玩家视角，对拍卖系统每条操作路径做**逐步模拟走查**（入口 → 点击 → 服务调用 → 数据变化 → 异常分支），验证不存在逻辑问题与资金/物品不一致 bug。
> 方式：逐行追踪代码路径 + 状态机推演 + 并发时序分析。
> 结论：**修复 10 处问题（含 1 处致命、1 处严重）后，全部玩家场景逻辑闭环、资金物品守恒。**

---

## 1. 模拟环境设定

- 玩家 A（卖家）、玩家 B/C（买家）、玩家 D（最高出价者）
- 经济：Vault（`bid-pay-immediately: true` 默认"出价即冻结"）
- 拍卖参数：起拍 100，一口价 200，加价幅度 10，时长 24h，自动延期开启（最后 5 分钟出价顺延 5 分钟），成交税 5%

## 2. 场景走查（8 大玩家路径）

### 场景 1：玩家 A 创建拍卖 ✅

| 步骤 | 玩家操作 | 代码路径 | 状态/数据 |
|---|---|---|---|
| 1 | `/spm auction create`（手持钻石×32） | `AuctionArguments.execute` → `GuiAuctionCreate.open` | GUI 打开 |
| 2 | 构造预览 | `Impl.doSearch`：手持物品包装为展示 Auction | '拍' 槽显示钻石 + `%create_price%` 等 |
| 3 | 左键 '价' ×3 | `handleOtherClick('价')` → `startPrice += 10` → `refreshState()` | 起拍价 1→31；`doSearch` 重建预览，**已设参数不丢** |
| 4 | 左键 '口' | `buyNowPrice = startPrice×2` | 一口价 62 |
| 5 | 左键 '时' | 循环 `DURATIONS` | 24h |
| 6 | 左键 '确' | `createAuction(player, hand, 31, 62, 0, 1440, true, cb)` | — |
| 7 | 主线程 | `containsAtLeast` 校验 → `removeItem(钻石×32)` | 背包扣 32 钻石 |
| 8 | 异步 | 上限校验 → 上架费(0) → `insertAuction` → 广播 | **data 列写入物品 YAML（本轮修复点①）** |
| 9 | 回调 | `closeInventory` + 打开主菜单 + `create__success` | 全流程成功 |

**异常分支**：手持空 → `create__no_item`；起拍价低于最低 → GUI 层 `startPrice` 起点已 ≥1；背包物品不足 → `create__no_enough_items` + 不扣物品；上限已达 → `create__limit_reached` + `rollbackItem` 归还；插入失败 → 归还物品。

### 场景 2：玩家 B 浏览列表与翻页/排序 ✅

| 步骤 | 操作 | 代码路径 | 验证点 |
|---|---|---|---|
| 1 | 主菜单 '览' | `GuiAuctionList.open` → `doSearch` | `countActiveAuctions` + 当前页 28 条 |
| 2 | '序' 左键（下一页） | `ActionAuctionPage` → `turnPageDown` → **`doSearch`（本轮修复点⑦：totalCount 同步刷新）** | 分页标题 `%max_page%` 正确 |
| 3 | '排' 左键 | `ActionAuctionSort` → 打开新排序 Impl | `price_asc/desc/newest/time_left` 循环 |
| 4 | 第 3 页点拍卖 | `onClickAuction` → **`parent.page = this.page`（修复点④）** | 详情打开 |
| 5 | 详情 '返' | **`parent.open() + refreshGui()`（修复点⑤）** | 回到**第 3 页**且数据刷新 |

**边界**：第 1 页 '序' 右键（上一页）→ `turnPageUp` 的 `page-1<1` 保护直接返回；空列表 → '空' 图标占位。

### 场景 3：玩家 B 出价（含自动延期） ✅

| 步骤 | 操作 | 代码路径 | 资金/数据 |
|---|---|---|---|
| 1 | 详情 '出' 左键 | `AuctionService.bid(B, id, 110, cb)` | 最低可出 = 100+10 |
| 2 | 校验 | 非本人、`amount≥nextBidAmount` | 110 ≥ 110 ✓ |
| 3 | 扣款 | `currency.has(B,110)` + `takeMoney(B,110)` | B 余额 −110 |
| 4 | CAS | `updateAuctionIfVersionMatches(updated, v)` | currentBid=110, bidder=B, **bid-count=1（修复点⑧）** |
| 5 | 退旧 | 无旧出价者 → 跳过 | — |
| 6 | 流水 | `putBid` + `bid__success` | 通知成功 |

**异常分支**：出价 105 < 110 → `bid__too_low`（**不扣款**）；余额不足 → `bid__not_enough`（**不扣款**）；CAS 冲突（别人抢先）→ `giveMoney(B,110)` 退回 + `bid__fail`；**旧出价者退款只在 CAS 成功之后执行（修复点②，杜绝"退款后冲突"账实不符）**。

**自动延期**：剩余 3 分钟时 B 出价 → `inExtendWindow` → `endAt = now+5min` → `bid__extend_notice`。顺延只发生在**出价成功**时（CAS 通过后 newEnd 已包含）。

### 场景 4：玩家 C 一口价 ✅

| 步骤 | 操作 | 代码路径 | 资金/数据 |
|---|---|---|---|
| 1 | 详情 '口' | `buyNow(C, id, cb)` | 一口价 200 |
| 2 | 校验 | 非本人、`buyNowPrice>0`、`has(C,200)` | ✓ |
| 3 | 预占 | `withStatus(FINISHED)` CAS（version 匹配） | 防双买（T7 并发专项） |
| 4 | 扣款 | `takeMoney(C, 200)` | C −200 |
| 5 | 付卖家 | `giveMoney(A, 200×0.95=190)` | A +190（税 10） |
| 6 | **退旧出价者** | `refundBidder`（**资金全部到位后，修复点②**） | D +110 解冻 |
| 7 | 交付 | 背包有空间 → `addItem`；满/离线 → `queueClaim` | 物品必达（背包或待领） |
| 8 | 通知/广播 | `sold__seller_notice` + `buy_now__success` + 广播 | 全链路 |

**异常分支**：扣款失败 → `rollbackToActive`（**旧出价者未退款，无损失**）；付卖家失败 → `giveMoney(C,200)` 退款 + 回滚；预占冲突 → `buy_now__fail`。

### 场景 5：玩家 A 取消拍卖 ✅

| 步骤 | 操作 | 代码路径 | 结果 |
|---|---|---|---|
| 1 | 我的拍卖 → Shift+左键 或 详情 '取' | `cancelAuction(A, id, cb)` | 校验本人 + ACTIVE |
| 2 | CAS 置 CANCELLED | `withStatus(CANCELLED)` | 防并发重复取消 |
| 3 | 退最高出价者 | `refundBidder`（出价即冻结 → D +110） | D 押金解冻 + 通知 |
| 4 | 退物品 | 在线背包有空 → `addItem`；满/离线 → `claim.seller.items` | 物品必达 |

**边界**：非本人 → `cancel__not_own`；非 ACTIVE → `cancel__not_active`；**流拍/取消离线退的物品现在可正常领取（修复点③：卖家领取同时处理 money+items）**。

### 场景 6：到期自动成交/流拍 ✅

**成交**（有最高出价者 D，出价 110）：
1. `AuctionExpireTask`（30s 周期，**从 AuctionConfig 读间隔——修复点⑥**）→ `processExpired`
2. `getExpiredUpTo(now, 200)` 只查 ACTIVE
3. CAS 置 FINISHED →（冻结模式已扣款）`giveMoney(A, 110×0.95=104.5)` → 交付物品给 D（离线/背包满 → 待领）
4. 通知双方 + 广播

**异常分支**：卖家入账失败 → **先退买家款（冻结模式无需退；非冻结模式 `giveMoney(D,110)`）再回滚（修复点②）**；CAS 冲突 → 跳过（下轮不再查，因状态已变）。

**流拍**（无人出价）：CAS 置 EXPIRED → 退物品给卖家 → `expired__seller_notice`。

### 场景 7：玩家领取待领区 ✅

| 侧 | 领取内容 | 代码路径 | 验证 |
|---|---|---|---|
| 卖家 | 成交款 + 流拍/取消退物 | `claim(true)`：先主线程给物品 → `finishSellerClaim` 清 money+items | 款项入账 + 物品入包，**修复点③/⑨（显示真实物品名）** |
| 买家 | 拍得物品（离线/满包场景） | `claim(false)`：给物品 → 清 `claim.buyer.items` | 物品必达 |
| 任一 | 无可领 | `claim__nothing` | 提示 |

**边界**：背包全满 → `giveItems` 返回 0 → `claim__inventory_full`，**待领区保留不误清**；`UtilsGive` 部分发放时剩余物品掉落脚下（不吞物品）。

## 3. 并发与资金一致性专项

| # | 场景 | 推演 | 结论 |
|---|---|---|---|
| C1 | 双人同时一口价 | 两人都过 `has` 校验 → 第一人 CAS 预占成功 → 第二人 `updateAuctionIfVersionMatches` 失败（version 已 +1 且 status≠ACTIVE）→ `buy_now__fail` | **恰好一人成交** |
| C2 | 出价 vs 一口价竞争 | 先出价者 CAS 成功 → 一口价者预占失败；反之亦然 | 单写者保证 |
| C3 | 出价扣款后 CAS 冲突 | `takeMoney` 已扣 → CAS 失败 → `giveMoney` 退回 | 资金守恒 |
| C4 | 旧出价者退款与冲突 | 退款**只在 CAS 成功后**执行；CAS 失败路径旧出价者分文未动 | 无"退款后回滚"漏洞 |
| C5 | 到期处理与手动操作并发 | `getExpiredUpTo` 只查 ACTIVE；到期处理 CAS 成功前，手动出价/取消仍可竞争同一 version | 状态机单方向收敛 |
| C6 | 断线/背包满 | 物品/款项全部走待领区（`claim.*`），无丢失路径；`finishSellerClaim` CAS 成功后才发钱 | 离线不丢资产 |
| C7 | 物品数据完整性 | **修复点①后 data 列包含完整物品 YAML**（此前新拍卖读回物品为 null → 列表崩溃/无法交付） | 存储闭环 |

**资金守恒验证**（成交示例 200 一口价，税 5%）：
- 进入：B 初始余额 X，D 冻结 110
- 变更：C −200，A +190，D +110（解冻），系统税 +10
- 守恒：−200 + 190 + 110 + 10 = +110（D 押金归还）✓ 与 B 无关，所有参与方账目闭合

## 4. 本轮模拟走查发现并修复的问题清单

| # | 严重度 | 问题 | 位置 | 修复 |
|---|---|---|---|---|
| ① | **致命** | `insertAuction` 把 data YAML 误写 `item` 列、`data` 列写空 → **新建拍卖读回物品丢失**（列表崩溃、无法交付） | AuctionDatabase | item 列置空、data 列写 `a.data().saveToString()` |
| ② | **严重** | `AuctionConfig` 从主 config.yml 读 `auction.*` → **auction.yml 全部配置永不生效**（税/上限/延期等全走默认） | AuctionConfig | 手动加载 auction.yml（仿 CurrencyManager），priority=990 |
| ③ | 中 | 流拍/取消离线退物写入 `claim.seller.items` 但领取逻辑只处理 money → **物品永久卡死** | AuctionService | 卖家领取同时清 money+items（finishSellerClaim） |
| ④ | 中 | 详情"返回"回到第 1 页（页码丢失） | GuiAuctionList/My/Bids | `parent.page = this.page` |
| ⑤ | 中 | 详情"返回"后列表数据不刷新（出价/取消后仍旧数据） | GuiAuctionDetail | '返' 先 `open()` 再 `refreshGui()` |
| ⑥ | 中 | `AuctionExpireTask` 从 config.yml 读周期 → 配置项失效 | AuctionExpireTask | 改读 `AuctionConfig.expireIntervalSeconds()` |
| ⑦ | 低 | 翻页后 `totalCount` 不刷新 → 分页标题滞后 | AbstractAuctionGui | `turnPageDown` 统一走 `doSearch` |
| ⑧ | 低 | `%auction_bid_count%` 占位符永远为 0 | AuctionService | `copyParamsWithBidCount` 出价/一口价后累加 |
| ⑨ | 低 | 卖家领取物品提示名显示"物品"占位 | AuctionService | 传真实物品名 |
| ⑩ | 低 | 我的拍卖/竞拍记录翻页按钮无效（动作只认列表 GUI） | ActionAuctionPage | 改为对 `IGuiPageable` 生效 |
| ⑪ | 低 | `isCitizensNpc` 每次右键 Class.forName | AuctionInteractListener | 静态缓存探测结果 |

## 5. 已知保留项（非缺陷，明示）

1. **未实际编译**：本机无 pluginbase 依赖 jar，代码按框架 API 自查（引用/括号/签名均已核对）；落地首步必须 `gradlew shadowJar`。
2. **12 条静态"SQL 拼接"告警为误报**：拼接对象仅为表名（配置）与 ORDER BY 白名单（switch 映射），所有用户输入走参数绑定，无注入面。
3. **GUI 主线程同步查库**（`doSearch`）：与 SweetPlayerMarket 原实现（GuiMyItems）一致；SQLite 下无感，MySQL 大数据量下可后续优化为全异步。
4. **经济接口同步性**：IEconomy 为同步方法，全部业务已包在 `runTaskAsync`，主线程无阻塞。
5. **多币种**：默认 `Vault`，其余（PlayerPoints/MPoints/CoinsEngine/Custom）经 `auction.currency` 切换，逻辑不变。

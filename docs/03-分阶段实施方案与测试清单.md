## 阶段 0：逻辑分析记录（已完成 ✅）

**产出**：`docs/01-PlayerAuctions深度技术分析.md`、`docs/02-XMPlayerMarketPlus集成设计.md`

| 关键结论 | 出处 |
|---|---|
| PlayerAuctions 的并发控制（预占 + 乐观锁 + 补偿回滚）是移植核心 | 01 文档 §3.2 |
| 竞拍/创建 GUI/搜索/SQLite 开关是原版缺口，本方案补齐 | 01 文档 §10 |
| SweetPlayerMarket 的 IEconomy 为同步方法，需自行异步化 | 02 文档 §5 |
| 数据库时间格式必须走 `Searching.format`（yyyy-MM-dd HH:mm:ss）兼容 SQLite/MySQL | 02 文档 §4 + 实测 |
| 拍卖数据落库走 `ItemSerializerManager`（NBT Base64）跨版本稳定 | 02 文档 §2.1 |

## 阶段 1：基础移植（数据层 + 业务层）

### 1.1 新增类（已完成代码）

| 类 | 关键方法 | 说明 |
|---|---|---|
| `auction/AuctionStatus` | `value() / valueOf(int)` | 状态枚举，与 PlayerAuctions 语义一致 |
| `auction/Auction` | `data() / fromData(...) / withStatus / withBid / nextBidAmount / inExtendWindow` | 不可变模型 + 乐观锁 version；补齐竞拍字段 |
| `auction/AuctionBid` | `BidType` 枚举 | 竞拍流水模型 |
| `auction/AuctionConfig` | `parseMinutes(str, fallback)`、`inst()` | auction.yml 配置映射（时长解析移植自 DurationParser） |
| `auction/AuctionDatabase` | `insertAuction / updateAuctionIfVersionMatches / getAuction / getActiveAuctions / getBySeller / getByBidder / getExpiredUpTo / putBid / getBidsByAuction` | HikariCP 建表（`{prefix}auctions` + `{prefix}auction_bids`），CAS 乐观锁 SQL |
| `auction/AuctionService` | `createAuction / bid / buyNow / cancelAuction / processExpired / claim / getActiveAuctions / getMyAuctions / getMyBids` | 全流程事务：预占→扣款→结算→交付→补偿回滚 |
| `auction/AuctionExpireTask` | `run()`（30s 周期） | 到期成交/流拍（对应 AuctionExpirer） |
| `auction/AuctionMessages` | 全部 `messages.auction.*` | i18n（LanguageManager 自动生成） |
| `auction/UtilsGive` | `giveItems(player, items)` | 背包发放工具 |

### 1.2 接入点修改

- `SweetPlayerMarket.beforeEnable()`：注册 `AuctionDatabase`（`options.registerDatabase`）、注册 `AuctionMessages`（`LanguageManager` 链）、注册 7 个动作 PROVIDER。
  **详见 `patches/INTEGRATION-POINTS.md` 修改 1。**

### 1.3 配置项（新增 `auction.yml`）

```yaml
auction:
  enabled / currency / max-auctions-per-player
  default-duration / min-duration / max-duration / min-start-price
  bid-increment / min-bid-increment / bid-pay-immediately
  expire-interval-seconds
  auto-extend: { enabled, trigger-minutes, extend-minutes }
  tax: { enabled, percent }
  listing-fee: { enabled, amount }
  broadcast: { on-create, on-sell, on-buy-now, range }
  mailbox: { enabled, retention-days }
  entrances: { auction-token, token-material, npc }
```

## 阶段 3：联调测试（实施清单）

### 3.1 环境准备

- Paper 1.20+（api-version 1.13 兼容链）或 Spigot 1.20；Folia/Canvas 可选
- 经济插件：Vault + EssentialsX（或 PlayerPoints/MPoints/CoinsEngine/Custom）
- Citizens（可选，验证 NPC 入口）

### 3.2 功能测试矩阵

| # | 场景 | 预期 | 涉及类 |
|---|---|---|---|
| T1 | 创建拍卖（手持物品 + 起拍价/一口价/时长） | 物品扣除、入库、广播 | AuctionService.createAuction |
| T2 | 浏览拍卖分页/排序 | 列表按时间/价格/最新排序 | GuiAuctionList / AuctionDatabase |
| T3 | 出价（高于最低加价） | 扣款、最高价更新、通知原出价者 | AuctionService.bid |
| T4 | 出价过低 | 拒绝并提示最低价 | bid / nextBidAmount |
| T5 | 余额不足出价 | 拒绝（bid-pay-immediately=true） | bid |
| T6 | 一口价 | 卖家得税后款、买家得物品、退款最高出价者 | buyNow |
| T7 | 并发出价/一口价竞争 | 仅一人成功（CAS 冲突者失败） | updateAuctionIfVersionMatches |
| T8 | 最后 5 分钟出价 | endAt 自动顺延 5 分钟 | bid / inExtendWindow |
| T9 | 到期有出价者 | 成交：卖家收款、买家得物品 | processExpired / settleWinningBid |
| T10 | 到期无人出价 | 流拍：物品退还卖家 | processExpired / settleExpiredNoBid |
| T11 | 取消拍卖 | 物品退还、最高出价者退款 | cancelAuction |
| T12 | 买家/卖家离线或背包满 | 物品/款项进待领区（params.claim.*） | deliverItem / queueClaim / claim |
| T13 | 领取待领款项/物品 | 正确入账，GUI 刷新 | claim |
| T14 | 上架费（开启时） | 创建前扣费，不足拒绝 | createAuction / listing-fee |
| T15 | 成交税（5%） | 卖家实收 = 成交价 × 0.95 | settleSellerAmount |
| T16 | 权限拦截 | 无 `sweet.playermarket.auction` 无法使用 | CommandMain / AuctionArguments |
| T17 | 重载配置 | `/spm auction reload` 无异常 | AuctionConfig.reloadConfig |

### 3.3 并发专项（重点，移植自 PlayerAuctions 的精华）

- 用 2 个客户端同时对同一拍卖出价/一口价，验证**恰好一人成功**（CAS）。
- 出价者在最后 5 秒出价，验证 endAt 顺延且仅顺延一次。
- 断线重连：购买过程中掉线，验证物品进入待领区而非丢失。

### 3.4 数据库专项

- SQLite：重启服务器数据不丢；`auctions` / `auction_bids` 表结构符合预期。
- MySQL：`{prefix}auctions` 的 DATETIME 读写正常（`Searching.format` 兼容）。
- 大数据量（>10 万条拍卖）下分页查询性能（`idx_auctions_status` 索引生效）。

### 3.5 回归测试（原功能不受影响）

- `/spm open`、`/spm me`、`/spm create`、领取、下架等原功能全部正常。
- 原市场 GUI 无拍卖按钮时不受影响（配置化入口）。
